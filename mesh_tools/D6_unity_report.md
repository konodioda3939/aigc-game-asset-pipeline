# 项目 D-6 验收报告：Unity 实测性能对比

> 测试日期：2026-07-01
> 测试样本：橙子模型（`tripoSR_orange.jpg` → TripoSR → 后处理）
> 测试环境：用户本地 Unity 项目，Game 视图 Stats 实测

## 1. 测试目的

用 Unity 实测数据证明：项目 D 的后处理（减面+展UV+LOD）能把 TripoSR 的"毛坯模型"打磨成"游戏可用"，且**渲染开销大幅下降**。

## 2. 对比样本

| 模型 | 来源 | 面数（mesh）|
|------|------|------------|
| `orange_RAW_19wan` | TripoSR 原始输出（resolution=256，未优化）| 191,108 |
| `orange_LOD0_8000` | 项目 D 后处理产出（Decimate 减面 + Smart UV Project 展UV）| 8,000 |

## 3. Unity 实测数据（Game 视图 Stats）

| 指标 | 毛坯 (RAW) | 优化后 (LOD0) | 变化 |
|------|-----------|--------------|------|
| **Triangles（三角面）** | 575k | 25.7k | **降 95.5%（×22.4）** |
| **Vertices（顶点）** | 1.2m | 67.5k | **降 94.4%（×17.8）** |
| FPS（单模型）| ~400 | ~400 | 持平（见说明）|

## 4. 数据解读

### 4.1 三角面/顶点大幅下降 = 渲染负载降 95%
GPU 渲染开销与三角面数正相关。**Tris 降 22 倍意味着显卡画这个模型只需 1/22 的算力**。这是"游戏可用"最硬的指标——游戏角色一般要求 <1 万面，优化后 8000 面达标，且可同屏大量铺放。

### 4.2 为什么 Unity Tris（575k）比模型面数（19 万）高？
Unity Stats 的 Tris 统计包含**整个渲染管线**：阴影投射 pass（Shadow Caster，每个 mesh 多渲染一遍）、顶点按法线/UV 拆分等。绝对值约为 mesh 面数的 ~3x。但**毛坯∶优化后的比例 ×22** 准确反映了优化幅度（与 mesh 面数比 19.1万/8000≈×24 一致）。

### 4.3 为什么 FPS 单测都是 400？
测试机配置较强，单个模型（哪怕 575k Tris）都能跑满帧。单测看不出 FPS 差异。但真实游戏场景同屏几十~上百个模型时：
- 毛坯：575k × N → 迅速压垮显卡，掉帧
- 优化后：25.7k × N → 依然流畅

> 想看 FPS 真实差异，可在场景里 Ctrl+D 复制 10~20 个模型做压力测试。
